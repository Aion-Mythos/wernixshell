# WernixShell: hard fork of caelestia-shell

WernixShell is the Hyprland desktop shell of WernixOS (Quickshell + Hyprland).
Hard fork of https://github.com/caelestia-dots/shell (GPLv3) at commit
`f80a98079b19f91f7d8a24218d068e77acc00025`. Upstream is not tracked after the fork.
All new files are GPLv3.

Work is split in 4 phases. Each phase ends with a STOP for manual testing.

## Phase 1: Rename / rebrand

Mapping (applied most-specific first by `scripts/rebrand.sh`):

| From | To |
|---|---|
| `Caelestia.<Mod>` (QML import/URI) | `WernixShell.<Mod>` |
| dir `plugin/src/Caelestia` | `plugin/src/WernixShell` (`git mv`) |
| `caelestia-<x>` CMake targets | `wernixshell-<x>` |
| `CAELESTIA_*` | `WERNIXSHELL_*` |
| `caelestia-drawers` etc. layer namespaces | `wernixshell-*` |
| `caelestia` CLI calls | removed (no external CLI; see Phase 3) |
| notify-send app `caelestia-cli` / `caelestia-shell` | `wernixshell` |
| XDG `.../caelestia` (utils/Paths.qml) | `.../wernixshell` |
| `caelestiaLogo`, `components/Logo.qml` | WernixOS logo, placeholder SVG |
| any remaining `caelestia`/`Caelestia`/`CAELESTIA` | `wernixshell`/`WernixShell`/`WERNIXSHELL` |

Rules:
- Script is idempotent and re-runnable; also renames files/dirs containing the name.
- `scripts/check-rebrand.sh` fails if `caelestia` (case-insensitive) remains anywhere except
  `LICENSE`, `NOTICE`, `CHANGES.md` (the rebrand/check scripts themselves are exempt since
  they must contain the patterns).
- Keep `LICENSE` and upstream copyright notices. Add `NOTICE` and `CHANGES.md`.
- Delete `flake.nix`, `flake.lock`, `nix/`. Strip Ko-fi/Discord badges and upstream install docs from README.
- Done when: plugin CMake build succeeds and `qs -p .` launches with no QML import errors.

## Phase 3: self-contained theme system

No external CLI. Bundled schemes are data (`data/schemes/<name>/<flavour>.json`, generated by
`scripts/gen-scheme.py` from `data/seeds`); `services/Themes.qml` lists and applies them by writing
`scheme.json`; the Dynamic scheme uses `matugen`; wallpapers are handled in QML. Theme Center page, launcher
`>scheme`/`>variant`, IPC `theme`, and an optional `on-theme-change` hook. Default scheme: wernixos dark.

## Out of scope

Bar placement (the bar stays fixed on the left, as upstream), floating bar, bar-only mode,
Updates/Plugins pages, new dashboard layout. Phase 4 (bar position) was built and then reverted.

## Constraints

Upstream code style and animation components. Small focused commits per step.
Nothing outside the listed deletions is removed without asking.
